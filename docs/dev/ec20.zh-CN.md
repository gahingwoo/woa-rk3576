# 泰山派 3M 上的 EC20 4G：Windows 下的移动数据

[English](ec20.md) | 简体中文

立创泰山派 3M 板载一个移远 EC20（USB `2C7C:0125`，测试板上固件为 EC20CEFILGR08A03M1G）。目标是在 Windows 11 23H2 里通过系统自带的 MBIM 类驱动和"设置 > 网络和 Internet > 手机网络"上网，不用移远的驱动。Windows 下的 COM 口、AT 工具、PIN、GNSS 和通话音频在 [gahingwoo/ec20-woa](https://github.com/gahingwoo/ec20-woa)；两个系统用的模式切换工具在 [`tools/ec20`](../../tools/ec20)。

状态：2026-11-26 在板上测过 Windows，**MBIM 没有数据**。切换本身成功（`usbnet` 为 2，MI_04 绑定 `cxwmbclass`），但这个固件从不回应 MBIM OPEN，见[这个固件上的 MBIM](#这个固件上的-mbim)。下一步试 [RNDIS](#rndisusbnet-3)，还没有完整测过。MBIM 模式下的 Linux 还没测。

## 决定：一次性切到 MBIM

EC20 出厂是 QMI/rmnet 模式（`AT+QCFG="usbnet",0`），Windows 驱动不了。`AT+QCFG="usbnet",2` 把网络功能变成 CDC MBIM，Windows 有自带驱动。这个设置存在模块的 NV 里，断电也保留。Linux 在 MBIM 模式下和 QMI 模式下一样能用，包括语音通话，所以只切一次，在哪个系统里切都行，固件什么都不做。

## 为什么 MBIM 模式下 Linux 照常工作

依据主线（linux-next，2026-09）和 ModemManager main（2026-11-17）：

| 部分 | MBIM 模式下 |
|---|---|
| `option.c` | 按接口类匹配 EC25/EC20 的 PID（DIAG、NMEA、AT、modem），两种模式下一样：ttyUSB0 到 ttyUSB3 不变 |
| `qmi_wwan.c` | `QMI_MATCH_FF_FF_FF(0x2c7c, 0x0125)` 不再匹配 |
| `cdc_mbim.c` | 匹配任何 `USB_CLASS_COMM` / `USB_CDC_SUBCLASS_MBIM` 接口；需要 `CONFIG_USB_NET_CDC_MBIM`（Armbian rockchip64 和 rk35xx 里是 `m`） |
| ModemManager | 移远插件允许 MBIM，创建 `MMBroadbandModemMbimQuectel`，它从 `MMBroadbandModem` 继承了基于 AT 的 Voice 接口：通话照常走 ttyUSB2；数据是通过 NetworkManager 的 MBIM 承载 |
| 通话音频（BSP 的 `lckfb-tspi-3m-modem-voice`） | 只用 AT，按 `ID_USB_INTERFACE_NUM` 02 和 03 匹配，这两个编号不变；UAC 功能排到两个 MBIM 接口之后，仍由 `snd-usb-audio` 按类绑定 |

**风险，要在板上确认：**

- BSP 脚本的 `early()` 只在 `USBCFG` 正好 9 个字段且 UAC 关着时才改写它。MBIM 模式下 `rmnet` 字段读出来可能不同；UAC 已经打开（已保存），所以应当不会写，但要在 MBIM 模式下读一次确认。
- ModemManager 的一位维护者 2020 年写过，MBIM 模式下的 EC25 不支持 MM 的初始 EPS 承载设置。测试 SIM 只支持 VoLTE；如果以后必须从 Linux 设置它的附着 APN，可能会在这里失败。
- Windows 的移动宽带服务可能把 APN 配置写进模块（预配的上下文会保留）。之后 Linux 看到的默认 APN 就不同了。

## Windows 需要什么

**一个 AT 口，用来切换。** AT 接口是厂商类 FF/00/00，Windows 不会给它绑驱动（usbser.sys 只对 CDC ACM，即 02/02，按类加载）。ec20-woa 里的 `ec20-ports.inf` 2.0 按兼容 ID `USB\COMPAT_VID_2c7c&Class_ff&SubClass_00&Prot_00` 把系统自带的 `usbser.sys` 绑到所有 FF/00/00 接口（NMEA、AT、modem），任何 usbnet 模式下都成立。1.0 版按硬件 ID 绑 MI_00..MI_03，在 RNDIS 模式下会把 MI_00（RNDIS 功能）从系统驱动手里抢走。没有它的话，就在 Linux 下切换。

| MI | usbnet 0，QMI | usbnet 2，MBIM | usbnet 3，RNDIS |
|---|---|---|---|
| 00 | DM FF/FF/FF | DM FF/FF/FF | RNDIS E0/01/03（含数据接口） |
| 01 | NMEA FF/00/00 | NMEA | （RNDIS 数据） |
| 02 | AT FF/00/00 | AT | DM FF/FF/FF |
| 03 | modem FF/00/00 | modem | NMEA FF/00/00 |
| 04 | QMI FF/FF/FF | MBIM 02/0E（含数据接口） | AT FF/00/00 |
| 05 | 音频 01 | （MBIM 数据） | modem FF/00/00 |
| 06 | | 音频 01 | 音频 01 |

哪些格是实测、哪些是推断，见 ec20-woa 的 README。DM 在任何模式下都没有驱动（它和 QMI 功能同为 FF/FF/FF），所以回归白名单里除了 MI_04 还有 MI_00 和 MI_02。

**MBIM 驱动。** 23H2 ARM64 镜像里的 `netwmbclass.inf`（DriverVer 10.0.22621.1，从泰山派的 `install.wim` 读的）匹配 `USB\class_02&subclass_0e&prot_00` 和 `USB\MS_COMP_MBIM`，服务名 `cxwmbclass`（`cxwmbclass.sys`，基于 MBBCx 的驱动）。不需要我们的 INF。它要求两个 MBIM 接口（02/0E/00 控制，0A/00/02 数据）组成一个功能，而 Windows 的复合设备驱动只有在有接口关联描述符（IAD）时才这样分组。这个固件所基于的高通 MBIM gadget 功能会声明 IAD，但这个模块还没测过；模式脚本会把单独出现的数据接口报为失败。

**不要按接口编号写 INF。** 任何 INF 都不能绑定 `USB\VID_2C7C&PID_0125&MI_xx` 这样的硬件 ID，空 INF 也不行：硬件 ID 匹配压过 MBIM 和 RNDIS 驱动的类匹配，而每个编号在某个模式下都是网络功能（MI_00 是 RNDIS，MI_04 是 QMI 或 MBIM）。

**固件版本。** 移远论坛上有一个 EC25-AU 要升级固件后才接受 `usbnet,2`，移远员工也说有些型号不支持 MBIM。脚本在复位前后都读回模式，没生效就停下。

**SIM 和 APN。** Windows 会自己要 SIM PIN。它按 SIM 的 IMSI/ICCID 从自己的运营商数据库里选 APN；如果运营商不在库里，在"设置 > 网络和 Internet > 手机网络 > 高级手机网络设置 > 添加 APN"里加（只支持 VoLTE 的 SIM 选类型"Internet 和附着"）。数据可能按流量计费；"让 Windows 保持我的连接"默认开着。

## 这个固件上的 MBIM

在泰山派上（EC20CEFILGR08A03M1G）对一次全新的模块复位抓了 USB 跟踪（`Microsoft-Windows-USB-USBHUB3`、`Microsoft-Windows-wmbclass`、`Microsoft-Windows-Wmbclass-Opn`）：

- `cxwmbclass` 初始化正常：GET_NTB_PARAMETERS、RESET_FUNCTION、SET_NTB_INPUT_SIZE、数据接口 alt 1 都完成了。
- 它发出 MBIM OPEN（SEND_ENCAPSULATED_COMMAND，16 字节，模块确认了这次传输），12 秒和 36 秒时重发，72 秒时发 CLOSE。本该带回 RESPONSE_AVAILABLE 的中断 IN 传输一直没有完成：模块从不回答。
- 大约 80 秒时驱动停掉设备，显示代码 43（CM_PROB_FAILED_POST_START）。`pnputil /restart-device` 只换来又一轮 80 秒的"正常"和同样的结局。WWAN 接口从未建立，所以 `netsh mbn show interfaces` 为空，WWAN-SVC 日志也为空。

这不是启动时序问题（复位后、重启后、几分钟后再重启设备都一样），也不是 SIM 的问题（OPEN 在任何 SIM 访问之前；已打开的设备会把锁 PIN 的 SIM 显示为"需要 PIN"）。移远论坛上有人报告 EC20CEFAG 固件同样"MBIM 模式下没有响应"。`ec20-mode.ps1` 现在会等待这个接口，这种情况下退出码为 6。

下一步，按顺序：

1. MBIM 模式下的 Linux（测试计划第 3 步）：`mbimcli -d /dev/cdc-wdm0 --query-device-caps`。如果那边也超时，就确定是固件问题。
2. 向移远要一个 MBIM 可用的 EC20CE 固件。
3. 不用移远驱动的退路：`usbnet` 3，见下文。

每次启动失败都会留下一个"Cellular N"网络接口（不存在、同一个 PnP 实例，位于 `Control\Network\{4D36E972-...}` 和 `Control\NetworkSetup2\Interfaces`）。它们无害，只是让下一个名字变成"Cellular 18"。

## RNDIS（usbnet 3）

系统自带的 `wceisvista.inf` 匹配 `USB\Class_E0&SubClass_01&Prot_03`。它是以太网适配器（"Remote NDIS based Internet Sharing Device"），不是手机网络：没有设置页、不弹 SIM PIN、没有 APN 界面。由模块拨号和做 NAT，适配器通过模块的 DHCP 拿一个私网地址。

泰山派实测（2026-11-26）：`AT+QCFG="usbnet",3` 回 ERROR，但读回是 3（和 usbnet 2 同样的怪癖）；`AT+CFUN=1,1` 之后各接口的类如上表。用 ec20-ports.inf 1.0 时 MI_00 被绑上 usbser 并启动失败（代码 10），MI_04/MI_05 没有驱动。

拨号：移远的 ECM/RNDIS 拨号命令 `AT+QNETDEVCTL=<op>,<cid>,<urc_en>`（`1,1,1` 表示连接上下文 1 并上报 URC）在 EC200 系列上有；论坛上一个 EC25-E 的报告说 EC2x 固件不认识它，EC2x 的 ECM 指南也只设 APN 再复位（模块注册后自己拨号）。`-Connect` 先问 `AT+QNETDEVCTL=?`，支持才拨。

RNDIS 模式下的 Linux（推断）：`rndis_host` 绑接口 0，`option` 仍然创建 ttyUSB0..3，但在接口 2 到 5 上。BSP 的通话音频服务按接口编号 02 和 03 匹配，在这个模式下会失效；用 `ec20-mode.sh qmi` 切回（它按类找 AT 口）。

## 如果一种模式不够

只有上板测试发现 Linux 在 MBIM 模式下做不到某件事时才考虑：

- 由两个系统自己切换：Linux 的一个服务开机时读到 2 就设成 0，Windows 的一个计划任务读到 0 就设成 2。代价是换系统后的第一次开机多一次模块复位（20 到 40 秒）。
- 由 UEFI 切换：固件要为厂商类 AT 接口写驱动，每次启动多 10 到 15 秒，切换时再多 20 到 40 秒。没有实现。

由 Windows 驱动在关机时改回模式的方案被否决了：每次死机或断电后模式都会是错的。

## 工具

[`tools/ec20/ec20-mode.ps1`](../../tools/ec20/ec20-mode.ps1)（Windows，Windows PowerShell 5.1）对 VID 2C7C 的每个 usbser COM 口发 `AT`，用第一个回 OK 的：

```powershell
.\ec20-mode.ps1 -Status                     # 固件、usbnet、各 USB 功能及其驱动
.\ec20-mode.ps1 -Mode rndis                 # 询问、设置、读回、复位、检查 wceisvista 和网卡
.\ec20-mode.ps1 -Connect -Pin 1234          # PIN、APN、注网、拨号、等 DHCP、打印 IP
.\ec20-mode.ps1 -Connect -Apn cmnet         # 先把 APN 设到上下文 1
.\ec20-mode.ps1 -Mode mbim                  # 检查 cxwmbclass 和 WWAN 接口
.\ec20-mode.ps1 -Mode qmi                   # 改回出厂默认（-Revert 效果相同）
```

[`tools/ec20/ec20-mode.sh`](../../tools/ec20/ec20-mode.sh)（Linux，root）用 modem 口（第三个 FF/00/00 接口：03，RNDIS 模式下是 05），泰山派上 QMI 模式时 ModemManager 不碰这个口：

```sh
sudo ./ec20-mode.sh status
sudo ./ec20-mode.sh rndis   # 之后检查 rndis_host 已绑定
sudo ./ec20-mode.sh mbim    # 检查 cdc_mbim
sudo ./ec20-mode.sh qmi     # 改回，检查 qmi_wwan
```

两者的退出码：0 完成且检查通过；1 被拒绝或取消；2 读回值不符；3 没有 AT 口；4 模块没有回来；5 模式已设但预期的驱动没有绑定。仅 Windows：6 MBIM 驱动已绑定但模块从不回应 MBIM OPEN；7 SIM 需要 PIN 或 PUK，或 PIN 被拒；8 没有注网；9 RNDIS 网卡没拿到 DHCP 地址。

## 上板测试计划

两个系统，按这个顺序，用同一张 SIM。保留每一步的输出。

**1. Linux，QMI（基线）。** `sudo tools/ec20/ec20-mode.sh status`：`usbnet: 0`，接口 4 由 `qmi_wwan` 绑定。给一个已知号码打一次电话，确认双向都有声音（上行一直没有人确认过）。

**2. Linux，切换。** `sudo tools/ec20/ec20-mode.sh mbim`。通过：退出码 0，接口 4 由 `cdc_mbim` 绑定，ttyUSB0..3 不变。记录 `lsusb -v -d 2c7c:0125 | grep -B2 -A8 "Interface Association"`（给 Windows 的 IAD 问题）以及 ttyUSB3 上的 `AT+QCFG="USBCFG"`。

**3. MBIM 模式下的 Linux。** `mmcli -m any`：模块由移远插件识别，主端口是 MBIM，带 `voice` 接口；数据通过 NetworkManager 连上（对手机网络连接执行 `nmcli c up`，`ping -I wwan0 1.1.1.1`）；注网后语音服务记录 "voice over USB audio: ok"；拨出和接听各一次，双向有声。冷启动后重复通话：共 3 次开机。失败：MM 里没有 voice 接口，或 MBIM 下通话无声而 QMI 下有声（那就看按系统切换的方案）。

**4. Windows。** `.\tools\ec20\ec20-mode.ps1 -Status`：`usbnet: 2`，MI_04 类为 02/0E，服务 `cxwmbclass`，状态 OK，没有单独的 0A 功能。设置里出现"手机网络"；`netsh mbn show interfaces` 和 `netsh mbn show readyinfo *` 显示 SIM 就绪。连接，然后 `ping -S <手机网络 IP> 1.1.1.1`、浏览网页、下载 100 MB。飞行模式关开一次；重启两次：手机网络自动重连，不需要重新输入 APN。`regress.ps1`：`devmgr` 仍然 PASS（单独的 MBIM 数据功能会在那里显示为没有驱动的设备）。

**4b. Windows，RNDIS。** 装好 ec20-ports.inf 2.0 后：`.\tools\ec20\ec20-mode.ps1 -Mode rndis`，然后 `-Connect -Pin <PIN>`。通过：三个 usbser 口（MI_03..MI_05），MI_00 由 `wceisvista.inf` 绑定并有一个 Remote NDIS 网卡，拿到 DHCP 地址，`ping -S <IP> 1.1.1.1`，下载 100 MB。记录哪个口回了 AT，以及 `AT+QNETDEVCTL=?` 的回复。

**5. Windows 之后回到 Linux。** 再测数据和一次通话：Windows 可能把 APN 配置写进了模块（第 4 步前后各看一次 `AT+CGDCONT?`）。

**6. 改回的路径。** 在 Windows 上 `.\tools\ec20\ec20-mode.ps1 -Revert`，然后在 Linux 上 `sudo tools/ec20/ec20-mode.sh status`：`usbnet: 0`，`qmi_wwan` 已绑定。日常使用再切回 MBIM。
