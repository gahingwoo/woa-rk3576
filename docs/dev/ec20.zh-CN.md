# 泰山派 3M 上的 EC20 4G：Windows 下的移动数据

立创泰山派 3M 板载一个移远 EC20（USB `2C7C:0125`，测试板上固件为 EC20CEFILGR08A03M1G）。目标是在 Windows 11 23H2 里通过 Windows 自己的移动宽带栈（系统自带的 MBIM 类驱动和"设置 > 网络和 Internet > 手机网络"）上网，不用移远的驱动。这个模块在 Windows 下的驱动和辅助脚本（COM 口、AT 工具、PIN、GNSS、通话音频）在单独的仓库 [gahingwoo/ec20-woa](https://github.com/gahingwoo/ec20-woa) 里；本页记录架构上的决定和上板计划，两个系统用的模式切换工具在 [`tools/ec20`](../../tools/ec20)。

状态：本页内容还没有在板上以 MBIM 模式跑过。实测过的地方都标明了。

## 决定

EC20 出厂是 QMI/rmnet 模式（`AT+QCFG="usbnet",0`），Windows 没有这个模式的驱动。`AT+QCFG="usbnet",2` 把它的网络功能变成 CDC MBIM，Windows 有自带驱动。这个设置存在模块的 NV 里，断电也保留，所以上一个系统设成什么，下一个系统看到的就是什么。

问题是模式是否必须跟着系统走（由 Windows 驱动在关机前改回去，或由 UEFI 固件在交接时设置）。不需要：同一块板上的 Linux（Armbian、主线驱动、ModemManager）在 MBIM 模式下和 QMI 模式下一样支持 EC20，包括板上的语音通话，证据见下。所以方案是**一次性切到 MBIM**，在哪个系统里切都行，固件里什么都不做。按系统切换的方案连同代价写在最后，以防上板测试发现 Linux 在 MBIM 模式下少了什么。

## 为什么一种模式就够：MBIM 模式下的 Linux

**内核。** 来自主线的匹配表（在 2026-09 的 linux-next 树里读的）：

- `drivers/usb/serial/option.c` 只按接口类匹配 EC25/EC20 的 PID：`USB_DEVICE_AND_INTERFACE_INFO(QUECTEL_VENDOR_ID, QUECTEL_PRODUCT_EC25, 0xff, 0xff, 0xff)` 加 `NUMEP2`（DIAG 口，两个端点），以及 `(..., 0xff, 0, 0)`（NMEA、AT、modem）。这些接口在两种模式下都一样，所以 ttyUSB0 到 ttyUSB3 不变。
- `drivers/net/usb/qmi_wwan.c` 有 `QMI_MATCH_FF_FF_FF(0x2c7c, 0x0125)`：它绑定 FF/FF/FF 网络接口，MBIM 模式下没有这个接口了。
- `drivers/net/usb/cdc_mbim.c` 匹配任何 `USB_CLASS_COMM` / `USB_CDC_SUBCLASS_MBIM` 接口，不需要 VID/PID，所以 MBIM 模式下它会绑定 EC20。内核需要 `CONFIG_USB_NET_CDC_MBIM`；Armbian 的 rockchip64（current、edge）和 rk35xx vendor 内核配置都设成 `m`。

**ModemManager。** 移远插件（`src/plugins/quectel/mm-plugin-quectel.c`，ModemManager main 截至 2026-11-17）设置了 `MM_PLUGIN_ALLOWED_MBIM`，探测到 MBIM 口时创建 `MMBroadbandModemMbimQuectel`。`MMBroadbandModemMbim` 继承自 `MMBroadbandModem`，后者用 AT 实现了 Voice 接口（`mm-broadband-modem.c` 里的 `G_IMPLEMENT_INTERFACE (MM_TYPE_IFACE_MODEM_VOICE, ...)`），两个 MBIM 类都没有覆盖它。所以 MBIM 模式下通过 ModemManager（以及 GNOME Calls）打电话仍然可用，只是走 ttyUSB2 上的 AT 命令而不是 QMI 的语音服务。数据照常是通过 NetworkManager 的 MBIM 承载。

**本板的通话音频。** 通话音频的修复（BSP 里的 `lckfb-tspi-3m-modem-voice`，见 Armbian BSP 里关于 EC20 的说明）只用 AT：接口 02 在 `AT+QCFG="USBCFG"` 里打开 UAC 并等 SIM，接口 03（`ID_MM_PORT_IGNORE=1`）在注网后发 `AT+QPCMV=1,2`。udev 规则按 `ID_USB_INTERFACE_NUM` 02 和 03 匹配，这两个编号在 MBIM 模式下不变。UAC 功能的编号会往后挪（排在两个 MBIM 接口之后），仍由 `snd-usb-audio` 按类绑定。

**风险，要在板上确认：**

- BSP 脚本的 `early()` 只在 `USBCFG` 正好 9 个字段且 UAC 关着时才改写它。MBIM 模式下 `rmnet` 字段读出来可能不同；UAC 已经打开（已保存），所以应当不会写，但要在 MBIM 模式下读一次确认。
- ModemManager 的一位维护者 2020 年写过，MBIM 模式下的 EC25 不支持 MM 的初始 EPS 承载设置。测试 SIM 只支持 VoLTE；如果以后必须从 Linux 设置它的附着 APN，可能会在这里失败。
- Windows 的移动宽带服务可能把 APN 配置写进模块（预配的上下文会保留）。之后 Linux 看到的默认 APN 就不同了。

## Windows 需要什么

**一个 AT 口，用来切换。** AT 接口（MI_02）是厂商类 FF/00/00。Windows 自己不会给它绑驱动（usbser.sys 只对 CDC ACM，即 02/02，按类加载），所以干净安装的系统上这个模块没有 COM 口。ec20-woa 里的 `ec20-ports.inf` 按硬件 ID 把系统自带的 `usbser.sys` 绑到 MI_00..MI_03；2026-11-14 在板上实测：四个 COM 口，AT 口（COM6）对 `AT` 有应答。这里不需要新的 INF。没有它的话，就在 Linux 下切换。

**MBIM 驱动。** 23H2 ARM64 镜像里的 `netwmbclass.inf`（DriverVer 10.0.22621.1，从泰山派的 `install.wim` 读的）匹配 `USB\class_02&subclass_0e&prot_00` 和 `USB\MS_COMP_MBIM`，服务名 `cxwmbclass`（`cxwmbclass.sys`，基于 MBBCx 的驱动）。不需要我们的 INF。它要求两个 MBIM 接口（02/0E/00 控制，0A/00/02 数据）组成一个功能，而 Windows 的复合设备驱动只有在有接口关联描述符（IAD）时才这样分组。这个固件所基于的高通 MBIM gadget 功能会声明 IAD，但这个模块还没测过；模式脚本会把单独出现的数据接口报为失败。

**MI_04 上不要 INF。** 回归测试把 `USB\VID_2C7C&PID_0125&MI_04` 列入白名单（QMI 模式下没有驱动）。任何 INF 都不能绑定这个硬件 ID，空 INF 也不行：切换之后它会压过 MBIM 驱动的类匹配，因为两种模式下硬件 ID 一样。

**固件版本。** 移远论坛上有一个 EC25-AU 要升级固件后才接受 `usbnet,2`，移远员工也说有些型号不支持 MBIM。脚本在复位前后都读回模式，没生效就停下。

**SIM 和 APN。** Windows 会自己要 SIM PIN。它按 SIM 的 IMSI/ICCID 从自己的运营商数据库里选 APN；如果运营商不在库里，在"设置 > 网络和 Internet > 手机网络 > 高级手机网络设置 > 添加 APN"里加（只支持 VoLTE 的 SIM 选类型"Internet 和附着"）。数据可能按流量计费；"让 Windows 保持我的连接"默认开着。

## 如果一种模式确实不够

只有上板测试发现 Linux 在 MBIM 模式下做不到某件事（而且在 Linux 一侧修不了）时才考虑：

- **由两个系统自己按系统切换。** Linux 的一个服务在开机时读到 2 就设成 0，Windows 的一个计划任务读到 0 就设成 2。代价：换系统后的第一次开机多一次模块复位（20 到 40 秒没有模块），其他时候没有。简单，不涉及固件。
- **由 UEFI 切换。** 固件需要为厂商类 USB 接口写自己的驱动（MI_02 的批量端点，CDC 风格的控制线状态），等模块对 AT 有应答（上电后约 10 秒），在 `ExitBootServices` 之前按所选启动项设置模式，只有模式变化时才复位并等它重新枚举：每次碰到模块的启动多 10 到 15 秒，切换时再多 20 到 40 秒，而且 EDK2 里要多一条只为这一个模块服务的 USB 主机路径。既然有上面更便宜的办法，不值得做；没有实现。

由 Windows 驱动在关机时改回模式的方案被否决了：每次死机或断电后模式都会是错的，而那恰恰是最需要它正确的时候。

## 工具

[`tools/ec20/ec20-mode.ps1`](../../tools/ec20/ec20-mode.ps1)（Windows，Windows PowerShell 5.1）自己找到 MI_02（或 MI_03）的 COM 口：

```powershell
.\ec20-mode.ps1 -Status     # 固件、usbnet、各 USB 功能及其驱动
.\ec20-mode.ps1             # 切到 MBIM：询问、设置、读回、复位、等待、检查 cxwmbclass
.\ec20-mode.ps1 -Revert     # 改回 QMI（usbnet 0）
```

[`tools/ec20/ec20-mode.sh`](../../tools/ec20/ec20-mode.sh)（Linux，root）默认用接口 03，泰山派上 ModemManager 不碰这个口：

```sh
sudo ./ec20-mode.sh status
sudo ./ec20-mode.sh mbim    # 之后检查 cdc_mbim 已绑定
sudo ./ec20-mode.sh qmi     # 改回，检查 qmi_wwan
```

两者的退出码：0 完成且检查通过；1 被拒绝或取消；2 读回值不符；3 没有 AT 口；4 模块没有回来；5 模式已设但预期的驱动没有绑定。ec20-woa 的 `Set-Ec20UsbNet.ps1` 做同样的事，用的是 ec20-woa 的模块，需要明确给出 `-Port`。

## 上板测试计划

两个系统，按这个顺序，用同一张 SIM。保留每一步的输出。

**1. Linux，QMI（基线）。** `sudo tools/ec20/ec20-mode.sh status`：`usbnet: 0`，接口 4 由 `qmi_wwan` 绑定。给一个已知号码打一次电话，确认双向都有声音（上行一直没有人确认过）。

**2. Linux，切换。** `sudo tools/ec20/ec20-mode.sh mbim`。通过：退出码 0，接口 4 由 `cdc_mbim` 绑定，ttyUSB0..3 不变。记录 `lsusb -v -d 2c7c:0125 | grep -B2 -A8 "Interface Association"`（给 Windows 的 IAD 问题）以及 ttyUSB3 上的 `AT+QCFG="USBCFG"`。

**3. MBIM 模式下的 Linux。** `mmcli -m any`：模块由移远插件识别，主端口是 MBIM，带 `voice` 接口；数据通过 NetworkManager 连上（对手机网络连接执行 `nmcli c up`，`ping -I wwan0 1.1.1.1`）；注网后语音服务记录 "voice over USB audio: ok"；拨出和接听各一次，双向有声。冷启动后重复通话：共 3 次开机。失败：MM 里没有 voice 接口，或 MBIM 下通话无声而 QMI 下有声（那就看按系统切换的方案）。

**4. Windows。** `.\tools\ec20\ec20-mode.ps1 -Status`：`usbnet: 2`，MI_04 类为 02/0E，服务 `cxwmbclass`，状态 OK，没有单独的 0A 功能。设置里出现"手机网络"；`netsh mbn show interfaces` 和 `netsh mbn show readyinfo *` 显示 SIM 就绪。连接，然后 `ping -S <手机网络 IP> 1.1.1.1`、浏览网页、下载 100 MB。飞行模式关开一次；重启两次：手机网络自动重连，不需要重新输入 APN。`regress.ps1`：`devmgr` 仍然 PASS（单独的 MBIM 数据功能会在那里显示为没有驱动的设备）。

**5. Windows 之后回到 Linux。** 再测数据和一次通话：Windows 可能把 APN 配置写进了模块（第 4 步前后各看一次 `AT+CGDCONT?`）。

**6. 改回的路径。** 在 Windows 上 `.\tools\ec20\ec20-mode.ps1 -Revert`，然后在 Linux 上 `sudo tools/ec20/ec20-mode.sh status`：`usbnet: 0`，`qmi_wwan` 已绑定。日常使用再切回 MBIM。
